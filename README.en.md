# Retrostation

A **dual-screen game frontend** for Linux handhelds, also compatible with single-screen devices. Built on an SDL2 + Pillow rendering stack, tuned for the Anbernic **RG DS** (Buildroot / Weston / dual 640×480 DSI screens).

The top screen (DSI-1) is the interactive main view; the bottom screen (DSI-2) is a context panel showing the current game's cover / video and metadata. When only one display output is detected, it automatically falls back to a single-screen layout with zero loss of functionality.

---

## Features

- **True dual-screen experience**: top screen shows the game list / grid / cover-flow; bottom screen prioritizes video and falls back to cover for media linkage.
- **Three game views**: list / grid / cover-flow, cycled with the `X` button.
- **Two metadata formats**: **ES-DE `gamelist.xml` (read + write)** and **Pegasus `metadata.pegasus.txt` (read-only)**, merged by priority; the bottom panel names the file the current entry actually came from.
- **ES-DE media layout**: cover · video · logo · screenshot · fanart, in ES-DE's own folder names (`covers/`, `videos/`, `marquees/`, `screenshots/`, `fanart/`). Works with ES-DE's separate tree (`gamelists/` + `downloaded_media/`) or with everything inside the ROM directory (`<SYS>/gamelist.xml` + `<SYS>/media/`) — **same folder names either way, so moving between the two needs no renaming**.
- **Interoperable play state**: favorites / play count / last played are written back to `gamelist.xml`, interoperable with ES-DE / Batocera.
- **Pluggable data sources**: `data/sources/` plugin layer; a new format is one new file, with the UI and scanner untouched.
- **Bottom-screen video with sound**: ffmpeg pipeline software decoding; the soundtrack plays through ALSA and the **volume rocker** adjusts it (±5, takes effect at once); automatic fallback to cover when there is no video or decoding fails; measured ~4.5% single core.
- **Fast cold start, light footprint**: index cache + thumbnail cache, cold start to first frame ~1.2 s, resident memory ~40 MB.
- **Instant settings persistence**: theme / brightness / language / status bar written immediately, no restart needed.
- **Cross-platform ready**: only `platform/` is allowed platform-specific code; all dimensions go through theme tokens, preparing for a future Android app.

## Architecture

Three cleanly isolated layers, ensuring cross-platform and testability:

- **Platform abstraction (`platform/`)**: UI can only draw via `Canvas` and receive input via semantic `InputAction`; `data/` only asks the platform for paths and directory listings. Linux implementation is SDL2 + PIL + evdev; future Android reuses the same interface (Chaquopy / MediaPlayer).
- **Data layer (`data/`)**: scanning, indexing, media cache, data source plugins. Scan results go to `index.json`, full screen on launch.
- **UI layer (`ui/`)**: state machine + Painter + screen modules, all dimensions through `theme` tokens, no hardcoded pixels.
- **Dual-screen approach**: single-process dual-canvas, top screen drives, bottom screen links; when `screen_mode` is `single`, it collapses to a single canvas (detail bar sinks below the list).

## Quick Start: Deploy to Handheld

### One-click Deploy

```bash
# Replace <掌机IP> with your handheld's address (e.g. 192.168.1.50)
python scripts/deploy.py root@<掌机IP>             # Actual deploy (ssh/scp, needs key)
python scripts/deploy.py --dry-run root@<掌机IP>   # Print only, don't act
python scripts/deploy.py --reset   root@<掌机IP>   # Also clean /tmp/retrostation_*

# When device only has password (factory root/root), add --password, auto switches to paramiko
python scripts/deploy.py root@<掌机IP> --password root
# Or: export RETROSTATION_SSH_PASSWORD=root
```

> Requires `pip install paramiko` (only for password login). Windows' `ssh` cannot pass password non-interactively;
> in password mode `deploy.py` uses `scripts/remote.py` (paramiko SSH/SFTP).

Deploy pushes 4 types of files to the device:

| Source | Target | Description |
|---|---|---|
| `src/` | `/mnt/mmc/Roms/APPS/Retrostation/src/` | App code |
| `retrostation.sh` | `/mnt/mmc/Roms/APPS/Retrostation/retrostation.sh` | Launcher (crash protection + log rotation) |
| `packaging/APPS/Retrostation.sh` | **`/mnt/mmc/Roms/APPS/Retrostation.sh`** | APPS menu entry (must be in APPS **root**) |
| `packaging/APPS/Imgs/Retrostation.png` | `/mnt/mmc/Roms/APPS/Imgs/Retrostation.png` | APPS menu cover 240×180 |

After deployment, open **APPS** menu on device → select **Retrostation.sh** to launch. **Must enter from APPS menu** — SSH launch fails when the stock frontend holds the screen. All output goes to `/mnt/mmc/Roms/APPS/Retrostation/log.txt`.

### Controls

| Key | Platform page | Game preview page |
|---|---|---|
| Up/Down | No response on platform page | Move selection (list ±1, grid by row ±4; hold to repeat) |
| Left/Right | Switch platform | List ±10; grid, carousel ±1 |
| **A** | Enter game library | **Launch game** |
| **B** | — | Back to platform page |
| **X** | — | Switch list / grid / carousel |
| **Y** | — | Favorite / unfavorite |
| L1 / R1 | — | Page up / down |
| L2 / R2 | — | Jump to first / last |
| SELECT | — | Switch filter (all / has cover / missing cover) |
| START | Settings menu | Settings menu |
| FUNC **long press** | Exit confirm | Exit confirm |

> Up/Down keys only switch selection in the **game preview page**; use **Left/Right** to switch platforms on the platform page.
> FUNC key (BTN_TL2) **long press 0.8s** to exit. L3 / R3 are also bound to the same action, so you won't think you can't exit.

### Troubleshooting & Diagnostics

```bash
cd /mnt/mmc/Roms/APPS/Retrostation
PYTHONPATH=src python3 -m retrostation.main --scan-only      # Library scan summary
PYTHONPATH=src python3 -m retrostation.main --check FC       # A platform's metadata/media coverage
PYTHONPATH=src python3 -X utf8 scripts/screenshot.py /tmp/shots  # Headless render each UI

# Key mapping self-check
python3 scripts/probe_input.py --check-keymap
python3 scripts/probe_input.py --watch-any --seconds 20      # Dynamic code capture
python3 scripts/probe_input.py                               # List all input nodes

# Bottom-screen video self-check (needs ffmpeg)
PYTHONPATH=src python3 -X utf8 scripts/video_selftest.py
PYTHONPATH=src python3 -X utf8 scripts/video_selftest.py --make-demo FC
PYTHONPATH=src python3 -X utf8 scripts/video_selftest.py --system FC --ui /tmp/shots
```

### Key Environment Variables (not set by device APPS menu)

| Variable | Default | Description |
|---|---|---|
| `PYSDL2_DLL_PATH` | `/usr/lib` | Find libSDL2-2.0.so.0 |
| `XDG_RUNTIME_DIR` | `/var/run` | weston socket location |
| `WAYLAND_DISPLAY` | `wayland-0` | Multi-screen recognition depends on it |
| `RETROSTATION_ROM_ROOT` | `/mnt/mmc/Roms` | ROM library root |
| `RETROSTATION_CONFIG_DIR` | Launcher directory | Config/state written here |
| `RETROSTATION_KILL_OVERLAY` | 0 | Set to 1 to `pkill` leftover stock processes |
| `RETROSTATION_FONT` | auto | Custom font path, overrides default source-han-sans-cn |

### Video / sound / metadata config (`config.json`)

| Key | Default | Description |
|---|---|---|
| `bottom_video` | `true` | Bottom-screen video master switch; forced off in single-screen mode |
| `video_size` | `[288, 216]` | ffmpeg output size (decodes at actual bottom-screen media box size at runtime) |
| `video_fps` | `15` | Decode/playback frame rate |
| `bottom_refresh_ms` | `90` | Minimum redraw interval for static bottom-screen content |
| `video_sound` | `true` | Preview sound switch; `false` mutes the bottom-screen clip |
| `video_volume` | `70` | Preview volume 0–100, adjustable with the **volume rocker** (±5) |
| `metadata.esde_root` | `""` | ES-DE root (the folder holding `gamelists/` and `downloaded_media/`); empty reads the in-ROM `<SYS>/gamelist.xml` + `<SYS>/media/` |
| `metadata.sources` | `["esde", "pegasus"]` | Enabled data sources, in priority order |

Media lookup order: the explicit path in `gamelist.xml` → the ES-DE type folders under the media
root (`covers/`, `videos/`, …) → the older convention `Imgs/` · `video/` · `logo/` →
one-folder-per-game packs (`media/<game>/`).

> Full directory layouts and volume controls: sections 5 and 6 of [docs/USAGE.en.md](docs/USAGE.en.md).

## Build & Release

This project is **deployed directly as Python source**, no bytecode packaging. After changing `.py`, use `deploy.py` to push to device in one click (deployment file list see above "Quick Start: Deploy to Handheld").

```bash
python scripts/deploy.py root@<掌机IP>             # Push source to device
python scripts/deploy.py --dry-run root@<掌机IP>   # Print only, don't execute
python scripts/deploy.py --reset   root@<掌机IP>   # Clean device /tmp/retrostation_* before deploy
# When device only has password (factory root/root), add --password, auto switches to paramiko
python scripts/deploy.py root@<掌机IP> --password root
```

Before deploy, `deploy.py` automatically clears local `__pycache__` cache, avoiding bringing the dev machine's (e.g. Python 3.12) compiled `.pyc` to the device, which would conflict with the device's 3.11 interpreter.

> Historical approach `scripts/build_release.py` once compiled `.py` into `.pyc` for release (obfuscation only, not encryption, and bytecode can't cross Python major versions). Current version no longer packages; the script is retained only as a reference for special distribution needs.

## Usage Guide

Full guide see [docs/USAGE.md](docs/USAGE.md). The two most common things:

### Swap emulator core

**Method A (minimal change)** —— edit SD card `retrostation/config.json`:

```json
{ "core_overrides": { "gba": "vba_next_libretro.so" } }
```

**Method B (full customization)** —— create `retrostation/systems.json`, change name and extension together:

```json
{
  "version": 1,
  "systems": [
    {"key": "gba", "label": "GBA", "label_zh": "GBA", "core": "vba_next_libretro.so"},
    {"key": "fc",  "label": "Famicom", "label_zh": "红白机", "core": "nestopia_libretro.so"}
  ]
}
```

> `label` is the generic / English display name, `label_zh` is the Chinese display name. The UI auto-selects by current language; to add Japanese later, add a `label_ja` field, no code change needed. **Each system already has a default core configured, works out of the box, no mapping needed.**

### Custom platform background & Logo (home carousel cards)

> **Where the built-in art comes from**: the shipped platform backgrounds and logos come from the
> **NeoStation frontend**'s theme art (sources: 1024×1024 square backgrounds, 820×330 transparent
> logos), converted by `scripts/build_platform_art.py` into the formats this handheld decodes
> fastest before being packed in: backgrounds as `256×256` WebP, logos as `256×103` PNG with alpha.

Put files in SD card `retrostation/platform-art/`, auto-matched by system directory name (key), no config needed:

```
retrostation/
└── platform-art/
    ├── background/FC.jpg     ← FC card background (square)
    └── logo/FC.png           ← FC card Logo (transparent PNG)
```

Rule: filename case-insensitive (`FC.jpg` ≡ `fc.jpg`); your files **override** built-in same-key art; new platforms without built-in art show program-generated placeholder (gradient + system name), no error.

Common system default cores see [systems.reference.json](systems.reference.json) (full with alt cores and extensions).

| Item | Value |
